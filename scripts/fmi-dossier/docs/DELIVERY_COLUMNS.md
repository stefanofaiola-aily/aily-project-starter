# FMI dossier delivery: columns, sources and app handover

Updated 2 November 2026. Policy `fmi-dossier-v3`; JSON schema `fmi-dossier-delivery-v2`. Companion: [MEASURES.md](MEASURES.md).

## 1. Read these columns first

The delivery has a `Delivery` sheet, a second `Column guide` sheet explaining every field, and identical ordered keys in JSON `rows`. All existing keys remain; the original weighted delivery's **38 positions and headers A–AL are preserved**. For the 26 previously published scored brands, scores/displays/cards now match the **1300 workbook behind the existing HTML**, rather than alternative dossier methods or the separate 1606 handover revision. New/unpublished scores use dossier inputs.

**Use AW (`adjusted_forecast_vs_py_forecast_yoy`) for the NEW uplift-adjusted Q4/selected-target YoY versus PY forecast.** AV is before uplift; AX is the improvement in percentage points. AR is the new uplift rate and AT the new forecast amount. AL is frozen historical projection versus PY sales, not the updated result. Check AM for the actual selected calendar/fiscal target. In `Column guide`, filter `Delivery use` to `Recommended delivery`; also retain the applicable `Delivery qualification` fields so periods, parent proxies and unavailable values are clear.

| Columns | What they contain | Source and use |
| --- | --- | --- |
| A–L | Prospect, selected FMI/components/categories, email domains, company key | Published scores when explicitly supplied; dossier scores otherwise. L is the **single verified Light company_code**, despite the retained plural header. Never substitute its historical brand/parent code list. |
| M–R | Three descriptors and insights | Exact published card content for existing scored brands; generated dossier cards otherwise. Read their actual period/proxy labels. |
| S | Selected normalized FMI | Preserved published display for existing scored brands; current cohort min–max for new/unpublished scores. **This is the new exponential input.** |
| T–Y | Three KPI values and labels | Published card KPIs for existing scored brands; otherwise peer gap in pp, source social lift and own revenue growth as fractions. Alternative dossier measurements do not replace published card drivers. |
| Z–AA | Category and rank | Revised company-list assignment for the 32 listed brands; blank category and no rank for unlisted brands. Exact source in leaderboard_category_source. Competition rank on current rounded S, not the historical or live-app rank. |
| AB–AI | Historical sales/social supplement | Original snapshots. February headers may describe show-week, annual or matched-month windows. AG is **original source uplift**, not new exponential uplift. AH/AI retain source text, which may be stale. |
| AJ–AL | Historical Q4 sales YoY snapshots | Source sales / preceding-year Q4 **sales** −1. Despite the inherited “vs Baseline” heading, these are not forecast-versus-baseline rates. AL uses the original legacy-adjusted 2026 projection. |
| AM–AX | New forecast scenario | Period, subject, currency, multiplier, untreated baseline, new uplift, adjustment, adjusted forecast and PY-forecast comparison. These are the **new commercial results**. |
| Following columns | Original legacy reproduction, scope/quality, app context, raw inputs and audit | Read to explain or audit the headline. Do not display every audit field in the app or sum parent amounts across brands. |

Stable JSON keys, not Excel letters/headings, are the app contract. Fractions such as 0.09217 display as 9.217%. Dates and numbers stay typed. Missing is null/blank, not zero. Identifying column A and the header row are frozen.

### Compact HTML delivery differs from the full audit file

The 50-column `outputs/fmi-dossier-html/html-delivery.xlsx` keeps legacy importer
headers but selects different presentation values. AC/AE (`Q4 vs Baseline ’24/’25`)
contain **source_q4_sales_yoy_2024/2025** from full-delivery AJ/AK. AG contains the
new adjusted/PY forecast comparison from full-delivery AW. Do not use full-file
AC/AE (same-year baseline variances) for the HTML revenue history. Missing sales
YoY stays blank, not a substitute baseline variance. Social history is unchanged.

The visible dialog description is AH (`Insights Descriptive`), a short business
summary generated from final values. It shows the comparison table and one
`Historical comparison basis` note. AI (`Insights Statistics`) and `Revenue
methodology` remain audit detail in Excel/JSON and are not appended to the visible
description. Fendi's historical HTML revenue values are −2.92% (2024) and −3.43%
(2025); the new 2026 forecast comparison remains −0.01%. FMI and uplift do not change.

| Exact key | Meaning | Source | Influences the new exponential? |

### Forecast names and denominators

| Exact key | What it means | Do not confuse with |
| --- | --- | --- |
| `baseline_revenue` | Accepted **untreated current-target forecast**; baseline_source tells whether source workbook or Light snapshot | Last year's revenue or an already adjusted projection |
| `adjusted_forecast` | **New exponential** scenario: baseline × (1 + uplift_fraction) | Original source forecast or raw-score diagnostic |
| `source_projected_forecast` | **Frozen original** sales-workbook adjusted forecast | A baseline to uplift again |
| `source_legacy_adjusted_forecast` | Reproduces the old formula using source_display_fmi on the same untreated baseline | The new exponential scenario |
| `legacy_adjusted_forecast` | Old formula applied to current **raw_fmi**; a diagnostic, not necessarily the old workbook forecast | Original legacy reproduction |
| `prior_year_forecast` | Current Light snapshot for the previous comparable target year | Actual sales or an archived forecast vintage |
| `source_sales_2025` / `prior_year_actual` | Source-labelled historical Q4 sales / separately approved comparable actual | PY forecast, even where numbers coincide |
| `*_vs_py_forecast_yoy` | Named forecast / matching PY forecast −1 | Source AL or actuals YoY |
| `*_forecast_yoy` | Named forecast / explicitly comparable PY actual −1 | Forecast-to-forecast YoY |

**Fendi example:** preserved published raw 47.3, components 50.4/53.6/30, normalized **81.6** → approved exponential **8.728%**. Baseline EUR 517.275m → **new forecast EUR 562.423m**. Source FMI 81.6 → original legacy 7.32% → original forecast EUR 555.140m. Historical AL is −1.3085% versus source 2025 Q4 sales. New AW versus the separately checked PY forecast is **−0.0137%**, approximately −0.01%. Both denominators happen to be 562.5m but their source classifications differ. Raw-score legacy 47.3 gives 0%; it remains only a diagnostic. The superseded +0.436% used an unintended normalized FMI of 83.0.

A fresh DB query is **not** implied by the presence of a Light/shared source name. Dossier measurements are saved document transcriptions; forecast and registry facts are saved authenticated snapshots. Input amounts are not refreshed simply because the delivery is rerun. Dated vintage limitations remain in forecast_vintage_status and historical_eligibility.

The source headings are retained for comparison. Do not assume February social means a February show, all source sales are officially reported actuals, calendar Q4 equals fiscal Q4, or a parent proxy is brand revenue. Optional comments/views/followers/EBITDA panels are not invented when absent.

## 4. Native app handoff
The final flat Excel/JSON is what you hand over privately. The receiving team adapts it to the deployed app schema; **the JSON envelope is not directly `content_json`**.

| Delivery values | Native target / integration role | Important rule |
| --- | --- | --- |
| `company_code` | Report row retrieval/foreign key | Existing Light key. Not a domain, ticker or `brand_id`. |
| `name`, `app_category` | Native `name`, `category` | Category must be LUXE/PREMIUM/MASS_MARKET, not a guessed mapping of FAST FOLLOWER/RETAILER/OTHER. |
| `raw_fmi`, `display_fmi`, `overall_sentiment` | `overall.score`, `overall.normalizedScore`, `overall.sentiment` | Retain distinction between source headline and display normalization. |
| `one_core_insight` | `oneCoreInsight` | Use final current narrative. |
| `ir_score`, `ir_sentiment`, `ir_descriptor`, `ir_insight`, `ir_kpi`, `ir_kpi_label` | Native `momentum` signal | IR = 50% card; format KPI as pp. |
| Corresponding `social_*` fields | Native `social` signal | Format lift KPI as percent, retaining actual metric/platform. |
| Corresponding `trend_*` fields | Optional native `strength` signal | 20% Strength card; own-growth KPI does not redefine source Strength method. |
| `adjusted_forecast`, forecast currency/multiplier/target/proxy notes | Native `projection` display/text | Exponential scenario is recommended headline; retain legacy comparison separately. No scientific statistical-insight claim. |
| Reviewed source history | `projection.history` | Source-specific years/windows, not automatically annual actuals. Native schema requires 1–20 unique-year entries when publishing native content. |
| `scope`, source/method/forecast notes | `revenueMethodology` | Describe measurements and hybrid/proxy scenario clearly. Do not expose local filesystem paths to clients. |
| `leaderboard_*` | Separate delivery diagnostics / category-board preparation | Do not store company `rank`, `brands`, `rankings` or `boardStatus` in native report content. Shared app board composes its rank. |

The current flat schema does not provide a verified native website `domain`/`primaryDomain`, renderer choice, title/subtitle approvals, publication flags or artwork directives. These are integration inputs, not score measurements. A report also needs required native Momentum/Social signals and appropriate history; an available reported headline alone does not guarantee native renderability.

The receiving team must verify the deployed schema and explicit category/domain mappings using [fashion-momentum-agent-handoff.md](../fashion-momentum-agent-handoff.md). This workflow does not upload, create companies, change live app rankings or activate reports. Delivery-only ranks recalculate when explicit category assignments change.
